============================================================================
PROJECT REPORT: LECSCHEDULER - AUTOMATED ACADEMIC SCHEDULING SYSTEM
============================================================================

1. PROJECT OVERVIEW
------------------
LecScheduler is a production-ready, automation-first web application designed 
for academic institutions. It simplifies the complex process of managing 
timetables, substitutions, and real-time communication between administration, 
faculty, and students.

2. TECHNOLOGY STACK (LANGUAGES & TOOLS)
--------------------------------------
* Frontend:
  - HTML5: Semantic structure for web pages.
  - CSS3 (Vanilla): Modern, responsive styling with a focus on "Low-Infrastructure Design".
  - JavaScript (ES6+): Client-side logic and Firebase integration.
* Backend & Infrastructure:
  - Node.js: Runtime for backend logic and automation scripts.
  - Firebase Cloud Functions: Serverless backend for intensive tasks.
  - Firebase Firestore: NoSQL real-time database for structured data.
  - Firebase Auth: Secure, role-based user authentication.
  - Firebase Storage: Cloud storage for institutional assets (PDFs).
* Specialized Tools & APIs:
  - Google Gemini API (AI/ML): Advanced text extraction and timetable parsing from PDFs.
  - Puppeteer-core: Headless browser automation for end-to-end system verification.
  - pdf-parse: Low-level PDF data extraction.
  - Service Workers: For offline availability and PWA features.

3. CORE FEATURES
----------------
* AI-Powered PDF Parsing:
  - Automatically transforms complex timetable PDFs into 100+ structured lecture 
    records in seconds using the Gemini AI API.
* Role-Based Portals:
  - Admin: Institutional control, student/faculty management, and master seeding.
  - Faculty: Personal timetable management, lecture cancellation/rescheduling, 
    and student announcements.
  - Student: Personalized real-time timetable, instant updates, and notice board.
* Real-Time Conflict Detection:
  - Automatically identifies scheduling clashes when uploading new timetables or 
    rescheduling lectures.
* Real-Time Communication:
  - Integrated Semester Chat for instant interaction.
  - Push-like notifications for lecture cancellations and rescheduling.
* Institutional Master Reset:
  - One-click capability to seed/reset the entire institution's data across 
    multiple semesters (e.g., MCA Sem II, IV, VI, VIII).
* Security & Privacy:
  - Enrollment-based student authentication.
  - Strict Firestore security rules to prevent unauthorized data access.

4. SYSTEM SCOPE
--------------
* Institutional Management: Supports thousands of students and faculty members.
* Multi-Semester Support: Independent data isolation for each semester/year.
* Accessibility: Mobile-first design for students accessing schedules on the go.
* Low Infrastructure: Designed to run efficiently on free/low-cost tiers 
  (Firebase Blaze/Spark).

5. KEY ACHIEVEMENTS (FOR REPORT)
-------------------------------
* Implemented a "Master Seeding" system that populates 4 semesters and 8 
  sections with high-fidelity data in one pass.
* Integrated AI-driven parsing to eliminate manual data entry errors.
* Developed a robust E2E test suite that verifies system integrity across 
  all three portals using automated browser sessions.
* Optimized data structures for "Semester-Wise" filtering and reporting.

6. ARCHITECTURE SUMMARY
----------------------
* Client-Server: Single Page Application (SPA) architecture.
* Database Model: Nested collection structure (Semesters -> Lectures/Faculty/Students).
* Security Model: Firebase Auth tokens verified against Firestore security rules.
