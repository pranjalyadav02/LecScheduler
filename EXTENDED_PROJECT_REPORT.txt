ABSTRACT
--------------------------------------------------------------------------------
LecScheduler is an intelligent academic scheduling and timetable automation platform designed to simplify lecture management in educational institutions. Traditional scheduling methods are highly manual, time-consuming, and error-prone. Problems such as lecture clashes, classroom conflicts, delayed announcements, and inefficient timetable updates create severe operational difficulties for institutions. 

The proposed system introduces a modern cloud-based and AI-powered solution that automates lecture scheduling, substitution handling, timetable updates, and conflict detection in real-time. Developed using modern web technologies including HTML5, CSS3, JavaScript, Firebase Firestore, and Firebase Authentication, the system entirely replaces legacy paper-based workflows. 

LecScheduler employs an event-driven serverless architecture that supports instant real-time synchronization between students, faculty, and administrators. A standout feature of the system is its integration of Artificial Intelligence via the Google Gemini API, which intelligently parses uploaded timetable PDFs and converts unstructured data into machine-readable JSON formats, removing hours of manual data entry.

Furthermore, the system introduces advanced UI/UX concepts, including WhatsApp-style date-grouped chat interfaces, real-time unread notification badges, dynamic date calculations based on academic calendars, and atomic batch database transactions to ensure absolute data integrity during lecture cancellations and rescheduling. 

Keywords: Cloud Computing, Firebase, Artificial Intelligence, Scheduling System, Timetable Automation, Real-Time Database, Serverless Computing, Gemini API.

CHAPTER 1: INTRODUCTION
================================================================================
1.1 Overview
Educational institutions handle massive amounts of lecture data, classroom allocations, faculty schedules, and student timetables daily. Managing these operations manually or through basic spreadsheets inevitably leads to scheduling conflicts, inefficient communication, and excessive administrative effort. LecScheduler digitizes this entire pipeline.

1.2 Motivation
The motivation behind this project stems from the inherent mathematical complexity of academic scheduling (often classified as NP-Hard in computer science). When a faculty member is absent, finding a substitute without causing a double-booking conflict is a tedious manual task. Furthermore, when changes are made, broadcasting those changes to hundreds of affected students instantly is impossible with physical notice boards. 

1.3 Scope of the Project
LecScheduler is scoped to handle:
- Master Timetable parsing via AI.
- Faculty substitution and rescheduling with conflict prevention.
- Institutional announcements and targeted push notifications.
- Semester-wise group chatting for peer-to-peer and faculty-student communication.

CHAPTER 2: LITERATURE REVIEW & PROBLEM STATEMENT
================================================================================
2.1 Drawbacks of Existing Systems
Traditional timetable management is plagued by:
- High margin of human error during data entry.
- Severe lack of real-time schedule updates for students.
- Difficulty in managing spontaneous faculty substitutions.
- Resource conflicts (two faculties assigned to the same room).

2.2 The Need for AI in Education
With the advent of Large Language Models (LLMs), unstructured data extraction has become highly efficient. Legacy systems required administrators to manually type out 6-day timetables into databases. LecScheduler utilizes AI to read standard PDF timetables and instantly map them to database objects.

2.3 Proposed Solution
The proposed LecScheduler system introduces a cloud-based intelligent scheduling platform featuring:
- AI-powered PDF parsing for automated timetable generation.
- Seamless Lecture Rescheduling and Cancellation System with instant timetable updates.
- Advanced Real-Time Notification System with sender attribution and unread count badges.
- Faculty substitution management with collision detection.
- Live group chat with intelligent WhatsApp-style date-grouping.

CHAPTER 4: SYSTEM ARCHITECTURE & DATABASE DESIGN
================================================================================
4.1 Architectural Paradigm
LecScheduler uses a "Serverless Single Page Application (SPA)" architecture. The frontend connects directly to Firebase Firestore via WebSockets, eliminating the need for traditional REST API polling.

4.2 NoSQL Database Schema (Firestore)
The database is structured hierarchically for maximum read-efficiency:
1. `users/{uid}`: Stores role (admin, faculty, student), name, email.
2. `semesters/{semesterId}`:
   - `lectures/{lectureId}`: Stores subject, room, faculty UID, day, startTime, endTime, date, and status (scheduled/rescheduled/cancelled).
   - `notifications/{notifId}`: Stores type, title, message, fromName, sentAt.
   - `messages/{messageId}`: Stores text, senderName, timestamp (for Group Chat).

4.3 Entity Relationships
Unlike SQL databases, LecScheduler uses Document-Collection nesting. Lectures and Notifications are sub-collections of a specific Semester, ensuring that data is securely siloed and students only download data relevant to their current academic term.

CHAPTER 5: TECHNOLOGY STACK & AI INTEGRATION
================================================================================
5.1 Frontend Technologies
- HTML5 & CSS3: Used for responsive, mobile-first layouts utilizing CSS Grid and Flexbox. Custom CSS variables handle the dynamic styling and branding.
- Vanilla JavaScript (ES6+): Chosen over frameworks like React to maintain absolute control over DOM manipulation and minimize bundle size.

5.2 Backend Technologies (Firebase)
- Firebase Firestore: A NoSQL cloud database providing live WebSockets synchronization.
- Firebase Authentication: Handles secure login, password hashing, and token validation.

5.3 Google Gemini API Integration
Traditional PDF parsers fail at timetables due to complex tabular layouts and merged cells. LecScheduler integrates Google's Gemini API to act as a semantic understanding layer. The API is prompted to extract raw text and logically deduce subjects, timings, and faculty names, returning a structured JSON array that the database can natively ingest.

CHAPTER 6: IMPLEMENTATION DETAILS & CORE ALGORITHMS
================================================================================
6.1 Atomic Batch Transactions for Data Integrity
When a faculty cancels a lecture, two things must happen: the lecture status must update to "cancelled", and a notification must be generated. If one succeeds and the other fails, the system enters an inconsistent state. LecScheduler solves this using Firestore `batch.commit()`, ensuring both database writes succeed simultaneously or fail entirely.

6.2 Dynamic Lecture Date Calculation
Timetables usually denote "Monday" or "Tuesday". LecScheduler includes a dynamic algorithm that calculates the exact calendar date (e.g., "May 8") for the current week by mapping the target day against the current system date. This provides students with absolute clarity on when a lecture is occurring.

6.3 WhatsApp-Style Chat Grouping Algorithm
To improve the chat UX, an algorithm was implemented to sort messages by timestamp. As messages render, the algorithm checks if the date boundary has crossed compared to the previous message. If so, it injects a visual CSS separator (e.g., "Today", "Yesterday", "May 6, 2026").

6.4 Real-Time Notification Badge System
The system tracks unread announcements using browser `localStorage` to save the `lastSeen` timestamp. As live Firestore snapshots arrive, the algorithm counts how many notifications possess a `sentAt` timestamp greater than `lastSeen`, updating a red numerical badge in the UI instantly.

6.5 Global Institutional Clock Synchronization
A central `common.js` utility broadcasts a live, to-the-second institutional clock across the Admin, Faculty, and Student portals. This guarantees all users act on identical time boundaries.

CHAPTER 8: SOFTWARE TESTING
================================================================================
8.1 Testing Methodologies
LecScheduler underwent rigorous testing across multiple vectors:
- Unit Testing: Validating the date calculation and time-parsing logic independently.
- Integration Testing: Ensuring Firestore security rules correctly blocked unauthorized edits.
- Functional Testing: Verifying the end-to-end flow of cancelling a lecture and seeing the notification appear on the student screen.

8.2 Security Testing
Validation checks were performed to ensure cross-site scripting (XSS) prevention by sanitizing all chat inputs before rendering them to the DOM using textContent methodologies instead of innerHTML where applicable.

8.3 Detailed Testing Logs & Cases

- Status: PASS

- Actual Output: JSON correctly mapped subjects, rooms, and faculty strings.

Test Case 03: Atomic Batch Write (Cancellation)
- Description: Faculty cancels a lecture. System must update lecture status AND send notification simultaneously.
- Input: Cancel "Data Structures" lecture with reason "Medical Leave".
- Expected Output: Lecture status changes to 'cancelled'. A new notification is written to Firestore.
- Actual Output: Batch transaction successful. Student UI immediately reflects the cancellation.
- Status: PASS

Test Case 04: Dynamic Date Grouping in Chat
- Description: Send messages across different dates and verify separator injection.
- Input: Messages sent on May 5, May 6, and current day.
- Expected Output: UI injects "May 5", "Yesterday", and "Today" headers automatically.
- Actual Output: JavaScript parser correctly identifies timestamp boundaries and renders separators.
- Status: PASS

- Description: Verify the unread counter increments when a new announcement arrives.
- Input: Admin sends global announcement.
- Expected Output: Student portal displays a red '1' badge next to the Notifications tab without refreshing.
- Actual Output: Firestore snapshot listener triggered UI update instantly.

CHAPTER 9: CONCLUSION & FUTURE SCOPE
================================================================================
9.1 Advantages & Limitations
Advantages: Automated scheduling, absolute real-time synchronization, zero server maintenance via serverless architecture, and AI-driven data entry.
Limitations: Relies on continuous internet connectivity for live updates; the AI parser requires relatively clean PDFs to achieve 100% accuracy.

9.2 Future Enhancements
Future iterations could include:
- Native Android/iOS Mobile Application deployment.
- GPS/Geofencing based student attendance tracking.
- Predictive Machine Learning models to suggest the best optimal time slots for rescheduling without conflicts.
- Automated SMS/WhatsApp notifications via Twilio integration.

9.3 Conclusion
LecScheduler successfully demonstrates how modern cloud-native architectures and Artificial Intelligence can completely modernize academic scheduling. By solving the complex problems of timetable collision, data entry fatigue, and delayed communication, the system provides an innovative, scalable, and highly efficient operational backbone for modern educational institutions.
